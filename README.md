# Tasks web app

The web app for the Tasks demo: TypeScript, [TanStack Start](https://tanstack.com/start) and the
Astryx design system (`@astryxdesign/core` and `@astryxdesign/theme-neutral`). It talks to the
Tasks API in [`mudasar-rauf/ai-demo-api`](https://github.com/mudasar-rauf/ai-demo-api), whose
contract is copied byte for byte in [`docs/contracts/api.md`](docs/contracts/api.md).

## Install

You need Node.js 22.12 or later (CI uses Node 24).

```bash
npm ci
```

## Run against a local API

1. Start the API from `ai-demo-api` as its README says. It serves `http://localhost:8000`.
2. Start the web app:

   ```bash
   npm run dev
   ```

   It serves `http://localhost:3000`, the only origin the API's CORS rule allows, so the port
   is fixed: the server stops rather than move to another port if 3000 is taken.

The API's base URL comes from `VITE_API_URL`, `http://localhost:8000` when unset or empty. To
change it or turn on a screen, copy `.env.example` to `.env.local` and edit it. `VITE_*` values
are built into the browser bundle, so they are public: never put a secret in one.

To serve the production build: `npm run build`, then `npm start` (also on port 3000).

## Feature flags

Each screen is behind a build-time flag, off unless set to `true`. While a flag is off, its
route shows "Not built yet".

| Flag | Screen | Route |
|---|---|---|
| `VITE_FF_TASKS` | Tasks | `/` |
| `VITE_FF_TASK` | Task | `/tasks/$id` |
| `VITE_FF_SUMMARY` | Summary | `/summary` |

Remove a flag, and its check in the screen, once its screen has shipped.

## Test and check

```bash
npm test            # Vitest, once (npx vitest for watch mode)
npm run lint        # ESLint
npm run typecheck   # tsc --noEmit
npm run build       # the production build
```

CI (`.github/workflows/ci.yml`) runs all four on every pull request into `main`. Tests never
reach a real API: they use the in-memory mock in `src/api/mock.ts`.

## Layout

| Path | What it holds |
|---|---|
| `src/routes/` | The routes. Each file only renders its screen; the screen issues do not edit them. `__root.tsx` holds the document shell and the layout. |
| `src/routeTree.gen.ts` | Generated by TanStack Start's Vite plugin on `npm run dev` and `npm run build`. Committed; commit it again if it changes. |
| `src/components/` | Shared components: `AppLayout` and `AppNav`, `NotBuiltYet`, `LoadingState`, `ErrorState`. |
| `src/screens/<screen>/` | Each screen's component, its data hook and its tests. |
| `src/api/` | The contract's types, the typed client, `ApiProvider`, `useApiResource` and the mock. |
| `src/flags.ts` | The feature flags. |
| `src/test/` | Test setup and `renderWithRouter`. |

`docs/contracts/api.md`, `src/api/types.ts` and `src/api/mock.ts` change together: when the
contract changes, copy it again and update the types and the mock to match.

## Building a screen

Each screen issue changes only its own folder, `src/screens/<screen>/`:

- **Behind its flag.** The screen component already checks its flag; replace the "on" branch.
- **Data.** Write a hook in the screen's folder, such as `src/screens/tasks/useTasksData.ts`, on
  `useApiResource((api) => api.listTasks(status), [status])` from `src/api/useApiResource.ts`.
  It loads on mount and when the deps change, and `reload()` loads again.
- **The client.** Never build a URL or read `VITE_API_URL`. Use the client `useApiResource`
  passes you, or `useApiClient()` from `src/api/ApiProvider.tsx` for mutations
  (`createTask`, `updateTask`, `deleteTask`) in event handlers, then call `reload()`.
- **Loading and errors.** While `status` is `"loading"`, render `<LoadingState />`. While it is
  `"error"`, render `<ErrorState error={error} onRetry={reload} />`: a 501 says "Not built yet on
  the server", a 404 shows its detail with a link to Tasks, a 422 lists each message, and
  anything else says "Could not reach the API" with Retry. Show a form's 422 field errors inline
  from each error's `loc`.
- **The URL.** Read search parameters with TanStack Router's hooks in the screen's folder
  (`useSearch({ strict: false })`, `useNavigate()`); do not add loaders or edit `src/routes/`.
- **Components.** Use Astryx components only. Astryx links navigate through the router.
- **Tests.** Render with `renderWithRouter(path)` from `src/test/renderWithRouter.tsx`. It
  renders the layout and the screen in a test router, with a client bound to a fresh mock,
  returned as `mock`: `mock.seed([...])` to add tasks, `mock.notImplemented("listTasks")` for
  the server's 501. Turn the screen's flag on with `vi.stubEnv("VITE_FF_TASKS", "true")`.
